# Game Bible — حي الأشبال

> **مرجع رسمي للعبة**. يُستخدم كمصدر وحيد للحقيقة لأي AI Agent يولّد محتوى أو فعاليات أو assets للعبة.
> **قاعدة الذهب:** إذا لم تُذكر معلومة في هذا الملف، اسأل المستخدم — لا تخترع.

## 1. Game Overview

| الحقل | القيمة |
|------|--------|
| اسم اللعبة | حي الأشبال |
| النوع | لعبة كروت عائلية للأطفال (Family Card Game) |
| المرجع التصميمي | مستوحاة من Love Letter — مع تعديلات هوية وثيم |
| الجمهور المستهدف | أطفال العائلة |
| النشر | **خاصة** — للعائلة فقط حالياً (قد تُنشر مستقبلاً) |
| المنصة الحالية | تطبيق ويب (React + Vite) |
| اللغة | عربية (RTL) |
| الإحساس العام | دافئ · عائلي · مرح · لطيف · عربي معاصر |
| الكلمات المفتاحية | حي · أشبال · كروت · عائلة · مقهى · مكتبة · جيران · بستان |

### وصف قصير
لعبة كروت رقمية للعائلة يلعبها الأطفال فيما بينهم أو ضد ذكاء اصطناعي. كل لاعب يمثّل شخصية من **حي الأشبال** — حي عربي صغير فيه مقهى ومكتبة وتجار وجيران. كل بطاقة لها قدرة تُغيّر مجرى الجولة، والهدف أن تكون آخر من تبقى أو صاحب أعلى بطاقة عند نهاية المجموعة.

## 2. Core Vision

### الفكرة الأساسية
كروت Love Letter بثوب عربي عائلي — كل شخصية شبه قريبة من ذاكرة الطفل (صاحب المقهى، أمين المكتبة، الجارة، التاجر)، وكل جولة قصة قصيرة بين أهل الحي.

### لماذا اللعبة موجودة
- مساحة لعب آمنة بين أطفال العائلة بهوية عربية واضحة.
- بديل عن الألعاب الأجنبية بأسماء وأماكن مألوفة لهم.
- لاحقاً: قاعدة لفعاليات شهرية AI-driven تكبر مع العائلة.

### التجربة المطلوبة
- جلسة قصيرة (5-10 دقائق للجولة).
- قواعد بسيطة لكن قرارات ذكية.
- شعور بالانتماء لـ "الحي" — الشخصيات تتكرر بألوان وقصص مختلفة.

### ما يجعلها مميزة داخل العائلة
- شخصيات بأسماء أفراد العائلة الحقيقيين أو مستوحاة منهم (حامد، علوي، السقاف، العيدروس، حسين، أحمد، هاشم، حمزة).
- ثيم عربي بصري متناسق (خط Zanjabeel، ألوان دافئة).
- نظام تطوّر (متجر، فريمات، باكات، إحصائيات لاعب).

### النبرة العامة
**دافئة · عائلية · مرحة · بسيطة بصرياً** — لا عنف، لا مواضيع حساسة، لا أسلوب تنافسي قاسي.

- أي محتوى غير مناسب لعمر الأطفال.

## 4. Gameplay Rules

> مستخرجة من `src/constants/cards.js` و `src/engine/gameEngine.js`.

### عدد اللاعبين
- **vs AI:** 1 لاعب بشري + 3 ذكاء اصطناعي.
- **Pass-play:** 2-6 لاعبين بشريين على جهاز واحد.
- **Online:** متعدد اللاعبين عبر الإنترنت (موجود في `OnlineLobbyPage.jsx` و `WaitingRoomPage.jsx`).

### تركيبة المجموعة (Deck) — 16 كرت
| القوة | الاسم العام | العدد |
|------|-------------|------|
| 1 | صاحب/ة المقهى | 5 |
| 2 | أمين/ة المكتبة | 2 |
| 3 | التاجر/ة | 2 |
| 4 | الجارة اليقظة | 2 |
| 5 | مهندس/ة الكهرباء | 2 |
| 6 | قائد الفرقة | 1 |
| 7 | صاحب البستان | 1 |
| 8 | نجمة الحي | 1 |
| **المجموع** | | **16** |

### بداية الجولة
1. تُخلط المجموعة وتُخفى كرت واحد جانباً.
2. يأخذ كل لاعب كرتاً واحداً في يده.
3. اللاعب الأول يسحب كرتاً ثانياً ويلعب أحد كرتيه.

### كيف يفوز اللاعب
- **يكسب الجولة:** آخر لاعب لم يُستبعد، أو صاحب أعلى قوة بطاقة عند نفاد المجموعة.
- **يكسب المباراة:** أول من يصل لعدد جولات محدد (يُحدّد في إعداد المباراة).

### كيف يخسر اللاعب
- يُستبعد من الجولة عند:
  - تخمين بطاقته صحيحاً عبر قوة 1.
  - مقارنته مع لاعب أعلى عبر قوة 3.
  - رميه قوة 8 (لأي سبب).
  - إجباره على رمي قوة 8 عبر تأثير قوة 5.

### تأثيرات الكروت
| القوة | التأثير | تفاصيل |
|------|---------|--------|
| 1 | خمّن كرت لاعب — إن صح يُقصى | اختر لاعباً وخمّن كرته. إذا أصبت يخرج فوراً. لا يجوز تخمين قوة 1. |
| 2 | تشاهد كرت لاعب آخر سراً | تنظر لبطاقته وحدك. |
| 3 | قارن — الأضعف يُقصى | تقارن قوتك بقوته. الأقل قوة يخرج. تساوي = لا أحد يخرج. |
| 4 | حماية حتى دورك القادم | لا يستهدفك أي لاعب حتى دورك التالي. |
| 5 | أجبر لاعب يرمي كرته ويسحب غيره | اختياره يجوز على نفسك. إذا رمى قوة 8 يخرج. |
| 6 | بدّل كرتك مع كرت لاعب آخر | تبديل يدوي. لا يُعدّ رمياً. |
| 7 | يجب رميه إذا معك 5 أو 6 | قاعدة قسرية: لو في يدك قوة 7 + (5 أو 6) → يجب رمي 7. |
| 8 | إذا رُمي لأي سبب: تخرج فوراً | كرت كارثي — لا يُرمى طوعاً أبداً. |

### تعديلات على Love Letter الأصلية
- الأسماء والثيم عربية بالكامل.
- بعض الشخصيات لها نسخ بصرية متعددة (1, 1b, 1c, 1d, 1e للقوة 1) — نفس القدرة، صور مختلفة.
- نظام مباريات متعدد الجولات (وليس جولة واحدة).
- ذكاء اصطناعي مدمج للاعبين الافتراضيين.

### ملاحظات خاصة
- **قوة 7 = كرت قسري:** إذا اجتمع في يد اللاعب مع 5 أو 6 → يُجبر على رميه.
- **قوة 8 = كرت موت:** إذا خرج من اليد (طوعاً أو قسراً) → اللاعب يخسر الجولة.
- **قوة 4 = درع:** لا يمكن استهداف اللاعب المحمي بأي قدرة.

### قواعد إجبارية على التعامل مع الشخصيات
- **لا تضيف شخصية جديدة بدون موافقة صريحة.**
- **الأسماء المركّبة** (مثل "هاشم أحمد"، "محمد هاشم") = اسم الطفل + اسم الأب — ليست شخصيتين.
- **ألقاب العائلة** (حامد، علوي، السقاف، العيدروس، حسين) = لقب عائلة فقط — لا تُستخدم كشخصية مستقلة.
- **تشابه الأسماء:**
  - "محمد أحمد" (1e — صاحب مقهى) ≠ "محمد هاشم" (7 — صاحب البستان) ≠ "محمد العيدروس" (5b — مهندس كهرباء).
  - "نور حامد" (4 — جارة) ≠ "نور حمزة" (8 — نجمة الحي).
- **الجنس ثابت** لكل ID — لا تغيّره.
- **الدور ثابت** — صاحب المقهى يبقى صاحب مقهى، حتى في فعاليات جديدة.

### معلومة ناقصة
- 🔴 **Character sheets الفعلية** (ملفات المرجع البصري لكل شخصية) — موقعها وصيغتها غير مذكورة في الكود. **أحتاج المسار.**
- 🔴 **الشخصية والطباع** لكل ID — غير موجودة في الكود. **أحتاج وصف نفسي/شخصي مختصر لكل واحد** (مثل: "ماريه — هادئة، تحب الضيوف").
- 🟡 **العمر التقريبي** لكل شخصية (طفل / مراهق / بالغ) — الأدوار توحي ببالغين لكن اللعبة "للأطفال". **أحتاج توضيح.**

## 6. Character Sheet Usage Rules

> القاعدة المركزية: **الشخصية ثابتة. الحدث يتغيّر.**

### قواعد ثابتة لا تتغير أبداً (بدون موافقة صريحة)
- **الوجه** (شكل العيون، الأنف، الفم، تعابير الهوية الأساسية).
- **الشعر** (اللون، الطول، التسريحة الأساسية).
- **لون البشرة.**
- **الستايل العام** (نوع الرسم، طبقة الألوان، الحدود).
- **الملابس الأساسية / الزي المميز** (المريول، الكوفية، الخمار، إلخ).
- **الإكسسوارات الهويّاتية** (نظارة، طاقية، ساعة معينة) إن كانت جزء من تعريف الشخصية.

### قواعد قابلة للتغيير (بموافقة)
- **الوضعية (Pose)** — يمكن توليد وضعيات جديدة.
- **التعبير المؤقت** (فرح، تركيز، فضول) — ليس تعبير الهوية الأساسي.
- **الإضاءة المحيطية** حسب جو الحدث.
- **الإكسسوارات المؤقتة للحدث** (بالون عيد، شجرة رمضان، عَلَم وطني).
- **الخلفية** حسب موقع الحدث.

### استخدام character sheet كمرجع
1. كل توليد جديد يجب أن يرفق character sheet الأصل في الـ prompt.
2. الـ AI Agent يستخرج وصف الشخصية من الورقة المرجعية أولاً.
3. تتم مقارنة الناتج بالـ sheet قبل القبول.
4. أي اختلاف في عنصر هوية = رفض ومحاولة جديدة.

### إكسسوارات الفعاليات
- تُضاف فوق الشخصية، **لا تستبدلها**.
- مثال مقبول: ماريه + بالون عيد ميلاد + قبعة احتفال.
- مثال مرفوض: ماريه بشعر جديد لأن "الجو احتفالي".

## 7. Visual Style Guide

- إحساس "كرتون عائلي" بسيط — قريب من Pixar / Studio Ghibli لكن بثيم عربي.

- الواقعية المفرطة (Photorealism).
- الأنمي الياباني (Anime style).
- شخصيات نصف عارية أو ملابس غير محتشمة.
- مشاهد دموية، أسلحة حقيقية، عنف.
- خطوط حدّية حادة جداً (Comic-book style).
- ألوان نيون أو فلوريسنت.
- خلفيات مزدحمة بصرياً.

### معلومة ناقصة
- 🟡 **مرجع بصري نموذجي** (مثال موافق عليه + مثال مرفوض) — مفيد للـ AI Agent. **أحتاج نموذج.**

### جدول مواصفات الـ Assets

| النوع | المقاس | الصيغة | خلفية | ملاحظات |
|------|--------|--------|------|---------|
| بطاقة لعب | 512×768 تقريباً | `.webp` | كاملة (داخل البطاقة) | تشمل الإطار والإكسسوارات داخل الفن |
| أفاتار (c/l) | 512×512 | `.webp` | كاملة دافئة | يُقص بشكل دائري/مربع داخل الفريم |
| إطار | 512×512 | `.webp` | **شفافة** | المنتصف فارغ تماماً ليظهر الأفاتار |
| باك | 512×512 | `.webp` | كاملة | تصميم صندوق/علبة هدية |
| أيقونة | 256×256 | `.webp` / `.svg` | شفافة | للواجهات |
| موسيقى | — | `.mp3` | — | جودة متوسطة (128-192 kbps كافية) |
| الجودة | — | — | — | WebP quality ≥ 85 |

### شروط رفض الـ Asset
- أبعاد غير المطلوبة.
- خلفية كاملة على عنصر مطلوب شفاف (أو العكس).
- ضغط زائد يُظهر artifacts.
- لا يطابق الستايل البصري (انظر القسم 7).
- يكسر قاعدة هوية شخصية (انظر القسم 6).
- يحتوي نصاً غير مطلوب.
- جودة WebP أقل من 85.

## 11. Monthly Events System

> نظام فعاليات شهرية يقترحه الـ AI Agent ويوافق عليه المستخدم بمراحل (Approval Gates).

### أنواع الفعاليات المقترحة
- **مواسم دينية:** رمضان، عيد الفطر، عيد الأضحى، المولد النبوي.
- **مناسبات وطنية / عائلية:** اليوم الوطني، عيد الأم، عيد الميلاد لطفل في العائلة.
- **ثيمات الفصول:** صيف الحي، مطر الشتاء، عودة المدارس.
- **أحداث قصة الحي:** افتتاح المقهى، حفل المكتبة، سوق التاجر، ليلة نجمة الحي.

### Pipeline الفعالية الشهرية (مع Approval Gates)

```
┌─────────────────────────────────────────────────────────────┐
│  Gate 1: الفكرة                                              │
│  AI يقترح 3 ثيمات مع نبذة قصيرة → المستخدم يختار             │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Gate 2: القصة                                               │
│  AI يكتب قصة الحدث (3-5 فقرات) + الشخصيات المشاركة          │
│  → المستخدم يوافق / يطلب تعديل                              │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Gate 3: قائمة الـ Assets                                    │
│  AI يحدّد: كم صورة، كم إطار، كم موسيقى، كم أيقونة            │
│  + جدول الأبعاد والصيغ → المستخدم يوافق                     │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Gate 4: الـ Prompts                                         │
│  AI يكتب prompt لكل asset (بناءً على character sheet)        │
│  → المستخدم يراجع ويوافق                                    │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Gate 5: الـ Assets النهائية                                 │
│  AI يولّد ويعرض → المستخدم يقبل أو يرفض كل واحد على حدة     │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  Gate 6: الإصدار                                             │
│  AI يجهز PR بالملفات + كود الفعالية → المستخدم يدمج         │
└─────────────────────────────────────────────────────────────┘
```

### ما يحق للـ Agent اقتراحه
- ثيمات وقصص وجوائز.
- prompts للصور والموسيقى.
- إعادة استخدام شخصيات موجودة في سياقات جديدة.
- إطارات وأيقونات موسمية.
- نسب احتمالات للجوائز.

### ما يمنع تنفيذه بدون موافقة
- توليد asset نهائي.
- إضافة شخصية جديدة.
- تغيير قواعد لعب.
- نشر PR.
- تغيير أسعار أو ندرات قائمة.
- تعديل character sheet.

### تنسيق اقتراح الحدث (Output Template)
```yaml
event:
  id: e_2026_06_summer
  name: "صيف الحي"
  theme: "إجازة الصيف وأهل الحي يجتمعون في البستان"
  duration: "1-30 يونيو 2026"
  story: |
    [3-5 فقرات]
  rewards:
    - id: fr_summer_01
      type: frame
      rarity: rare
      drop_via: event_login_day_7
  characters_used: [7, 4, 8]
  assets_needed:
    - { id: fr_summer_01, kind: frame, size: 512x512, transparent: true }
    - { id: bg_summer,    kind: bg,    size: 1080x1920, transparent: false }
  prompts: {...}
```

## 12. AI Agent Rules

> قواعد إلزامية لأي AI Agent يعمل على هذه اللعبة.

### قواعد عدم الاختراع
1. **لا يخترع شخصية جديدة** — الـ 16 ثابتة.
2. **لا يخترع اسماً غير موجود في الجدول.**
3. **لا يخترع مكاناً غير موجود في عالم الحي.**
4. **لا يخترع قاعدة لعب غير موجودة هنا.**

### قواعد الهوية
5. **لا يغيّر وجه، شعر، لون بشرة، ستايل، أو ملابس أساسية** لأي شخصية بدون موافقة صريحة.
6. **لا يخلط شخصيتين** في صورة واحدة (إلا إذا طُلب صراحة لمشهد قصة).
7. **لا يخترع علاقات** بين الشخصيات غير المذكورة هنا.

### قواعد الستايل
8. **لا يغيّر الستايل البصري** (انظر القسم 7).
9. **لا يستخدم Photorealism / Anime / Comic-book.**
10. **لا يضع نصاً داخل الصور** إلا إذا طُلب نص محدد.

### قواعد التنفيذ
11. **لا يولّد asset نهائي قبل موافقة prompt.**
12. **لا يرفع ملف للمستودع قبل مراجعة المستخدم.**
13. **لا يفتح PR إلا بطلب صريح.**
14. **لا يعدّل ملفات لعب جوهرية** (`cards.js`, `gameEngine.js`, `packSystem.js`) بدون موافقة.

### قواعد الجودة
15. **يراجع كل asset قبل التسليم** ضد جدول مواصفات القسم 10.
16. **يقارن الصور المولّدة بـ character sheet** قبل القبول.
17. **يرفض ذاتياً** أي asset لا يطابق المعايير، ويعيد المحاولة.

### قاعدة الذهب
18. **إذا لم يعرف معلومة، يسأل المستخدم** بسؤال محدد ومختصر. لا يخمن، لا يفترض، لا يكمل بمعلومة "منطقية".
